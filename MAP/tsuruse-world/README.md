# 鶴瀬駅周辺 — 大型移動マップ / 道路判読版

添付の結合地図の道路色・建物形状を同じ座標のまま抽出し、ゲーム用の地形データと歩行サンプルを作成しました。元画像の道路位置を優先したベクター／ピクセル調の基礎マップです。以前の生成イラストとは描画方式が異なります。

## 試す
`preview.html` をブラウザで開きます。画像とデータを内包し、通信不要です。
- 全体図から「歩き始める」で開始位置へ拡大し、キャラクター追従に切り替え。
- 左下のパッド、矢印キー、WASDで移動。
- 道をタップすると、読み取れた道路の接続だけを使って自動移動。細い道はこの方法が便利です。
- 「元地図」「ゲーム表示」で同じ位置・倍率のまま比較。
- 「通行範囲」で抽出した通行候補を重ねて表示。
- 「全体」で全域へ戻り、ドラッグで見渡し、＋／−やマウスホイールで拡縮。
- 「開始地点を選ぶ」で別の区画の道路に開始位置を置けます。これは確認用の機能で、ゲーム中の通常移動とは別です。

## 正確さと確認が必要な箇所
道路を画像生成で描き直していません。元画像の2048×1885ピクセル座標に一致する領域を抽出し、道路の曲がり方や位置を固定しました。処理では道の膨張・穴埋め・継ぎ目の自動接続を行っていません。
ただし、色からの道路判読は完全ではありません。文字で隠れた区間、継ぎ目の段差、細い路地、線路・河川付近、立体交差は元画像だけでは確定できません。灰色の文字などの誤抽出・道路の欠落が残る可能性があります。
227,599画素の道路候補を採用し、最大の連続範囲は205,029画素（約90.1%）。連続範囲は全部で111個あります。111箇所の「誤り」という意味ではなく、正当な分離・画像端・文字隠れなどを含む未確定の区画数です。`review-points.json` に区画の範囲と代表座標を収録しています。未確定区画を無理につなぐことはしていません。
白い未収録部分は未探索扱いで進入不可。草地の描画はありますが、公園・学校・私有地の可否を判断できないため、この版で通れるのは道路候補だけです。駅名ラベルや正確な改札口位置は新規に推定していません。開始点は南西側の道路上の仮位置です。
添付地図の情報量が上限です。高倍率表示は追加の地理情報や測量精度を意味しません。本番ゲームへの反映前に通行範囲を元地図と照合してください。

## 大きさと描画
- 元画像／データ座標：2048 × 1885。
- 8倍表示時の論理ワールド：16,384 × 15,080。
- 原点＝左上、x＝右、y＝下。
- アプリ内の速度・開始位置・当たり判定はすべて元画像座標。表示のみ拡大。
- 巨大な16K画像をメモリ展開せず、2048サイズの背景をカメラで拡大描画。
- `game-map.svg` は拡大できるベクター背景。ただし地理情報の精細さは元画像と同じ。
- 建物は元の輪郭を用いた簡略屋根表現。生成イラストの建物・樹木を道路上に追加していません。

## ファイル
- `assets/game-map.png`：ゲーム表示用の軽量PNG背景。
- `assets/game-map.svg`：同じ地形のベクター版。
- `map-overview.png`：全体確認画像。
- `assets/reference.png`：提供された地図を無変更で収録した比較用画像。
- `map.json`：地形の寸法、道路RLE、開始位置、区画情報。schemaVersionは **2**。
- `terrain.bin`：1セル1バイト、row-major（y*width+x）。2048×1885セル。
- `navigation.js`：道路判定、移動、道路グリッド上の経路探索。
- `viewer.js` / `viewer.css`：歩行・追従・拡縮・比較表示。
- `TsuruseWorld.jsx`：React部品。
- `index.html`：HTTPサーバーで使う分離ファイル版。
- `preview.html`：単一HTMLの確認版。
- `review-points.json`：接続を要確認の区画一覧。
- `tests.mjs` / `validation.json`：ナビゲーション検証コード／結果。
- `build_map.py`：同じデータを再生成するPythonスクリプト。Pillow・NumPy・SciPyが必要。再生成後はSVGをPNGへ書き出してください。

terrain.binの値：0=未収録、1=地面、2=建物候補、3=緑地候補、4=水色の地物、5=道路候補。
通行判定は値5だけです。`roadRuns` は `[先頭セル番号,連続セル数]` の配列。階層や道路種別を持つ実測ベクターデータではありません。

## Reactへ取り込む
1. `map.json`、`terrain.bin`、`assets/` を `public/fields/tsuruse/` にコピー。
2. `navigation.js`、`viewer.js`、`viewer.css`、`TsuruseWorld.jsx` を `src/fields/` にコピー。
3. 表示先で以下を使用。

```jsx
import TsuruseWorld from './fields/TsuruseWorld.jsx';

<TsuruseWorld
  assetBase="./fields/tsuruse/"
  paused={false}
  onError={console.error}
/>
```

GitHub Pagesの `/-/` 配下に対応する相対URL。配置階層に合わせてassetBaseを調整してください。既存のアンビシャス／ゆうゆうの丘公園のschemaVersion:1エンジンとは別です。今回のviewerとnavigationを一緒に使用してください。既存の戦闘・セーブ・ステージ選択への接続やデプロイはしていません。

## 動作の範囲
当たり判定は足元1点で、最大0.15元画像ピクセルの小刻み移動です。細い線の形を維持するため、この版ではキャラクターの体全体で壁を判定しません。近接した図形の8方向接続は画像上の隣接判定で、立体交差を区別しません。
経路探索は8方向グリッドを使い、欠けた道路を飛び越えません。経路探索に使う道路データと描画は同じ座標で、選択地点へは同じ連続区画からしか移動できません。実装例の虫取り少年はCanvasの仮キャラクターです。作成済みのスプライトシートは今回の成果物に含めていません。
道路RLEとterrain.binの全セル一致、開始位置、経路の歩行追従、道路外拒否、離れた区画を勝手につながないことをNode.jsで検証しました。`node tests.mjs` で再現できます。ブラウザでの画面実行、スマホ実機、既存Reactアプリとの結合は未検証です。
