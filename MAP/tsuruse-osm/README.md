# つるせ・OpenStreetMap版（v5）

v1〜v4（AI生成イラスト）は道路の位置ずれ・解像度不足が解消できなかったため、
実際の地図データ（OpenStreetMap）に切り替えた。

## しくみ

- 背景：OSM標準タイル（zoom19、`https://{a,b,c}.tile.openstreetmap.org/{z}/{x}/{y}.png`）を
  29×29枚ダウンロードして並べたもの（1px ≒ 0.242m）。ライセンス：ODbL。
  アプリ画面に `© OpenStreetMap contributors` を表示している。
- 当たり判定：Overpass API で同じ範囲の `highway=*` の道路データを取得し、
  種別ごとの太さで自前でラスタライズしたマスク（`roadRuns`、既存の
  `src/fields/world/navigation.js` と同じ RLE 形式）。背景画像とは別データなので、
  ズレを防ぐには「同じ座標系で作る」ことが要点（緯度経度→タイルピクセル座標の
  変換式が両方で同一であれば、原理的にズレない）。
- タイル分割・読み込みの仕組みは v2/v4 と同じ `tile-store.js`（無変更）を流用。

## 中心・スポーン地点

- 中心座標：緯度35.8479 / 経度139.5380（鶴瀬駅とアンビシャスガーデン鶴瀬の中間）
- スタート地点：当初は「アンビシャスガーデン鶴瀬」をGoogle検索でジオコーディングした座標
  （35.8497311, 139.5361195）に最も近い道路点にしていたが、OSMにはこの施設が
  登録されておらず、ゲーム画面上の実際の見え方とズレていた。2026-09-24、ユーザーが
  全体地図のスクリーンショットに直接マークした地点（緯度35.849707 / 経度139.536283、
  map座標 3185, 2997。当初の座標から約27m）に修正。この点はもとから道路の上にあった
  ため、道路探索なしでそのまま採用。

## 再生成のしかた

`scripts/` に手順をまとめてある。Python（Pillow, numpy）が必要。

1. `download_tiles.py`：OSMタイルをダウンロード（zoom, 中心, 範囲を指定）
2. `fetch_roads.py`：Overpass API で道路データ(`roads-overpass.json`)を取得
3. `build_map.py`：道路マスクのラスタライズ、roadRuns変換、map.json/tiles.json生成

OSMタイルサーバーへの負荷に配慮し、ダウンロード間隔を空け、User-Agentを設定すること。
841枚（zoom19）で通信量は約7MB程度。

## 注意

- OSM標準タイルには「barrier=fence」等の赤い破線記号が写り込む場所がある
  （墓地の区画線など）。実際の地図情報として正確なので、そのまま使っている。
- 道路種別ごとの線の太さは目視確認しながら調整した値（`build_map.py`内）。
