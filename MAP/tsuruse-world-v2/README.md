# 鶴瀬駅周辺・分割読込マップ v2

スマホの歩行ゲーム向けに、近くの区画だけを読み込む実装です。元画像の座標を維持したSVGの道路・屋根・樹木を描画します。前回の小さい画像を引き伸ばしたものではありません。ただし、先に提示した生成イラストそのものを詳細化したものでもありません。見た目は地図の配置を優先したベクター調です。「アンビシャス」と同じ手描き風の品質を全域で再現した完成背景ではありません。

## まず試す

`preview.html` をブラウザーで開き、「歩き始める」を押してください。矢印/WASD、左下の移動パッド、道路のタップで移動します。プレイヤーを中心にカメラが追従します。

- `preview.html`: 単体確認用。素材を内包するため最初に全ファイル相当を読み込みます。アプリ本番用ではありません。
- `index.html`: 本番と同じ区画ごとのHTTP読込。フォルダーで `python3 -m http.server 8000` を実行し `http://localhost:8000` を開いてください。
- `detail-preview.png`: 1区画の描画見本。実際の歩行表示ではこの見本の約半分のCSS寸法になります。

## Reactアプリへの組み込み

1. `map.json`、`tiles.json` と `assets/` を、アプリの `public/fields/tsuruse/` に配置します。
2. `TsuruseWorld.jsx`、`viewer.js`、`viewer.css`、`navigation.js`、`tile-store.js` を同じソースフォルダーに配置します。
3. マップを表示したい画面で以下を使用します。

```jsx
import TsuruseWorld from './fields/TsuruseWorld.jsx';

export default function FieldScreen() {
  return <TsuruseWorld
    assetBase="./fields/tsuruse/"
    onPosition={({x,y}) => { /* 足元位置。元地図のピクセル座標 */ }}
    onError={error => console.error(error)}
  />;
}
```

GitHub Pagesのサブディレクトリでも、`assetBase`が実際の素材URLを指すようにしてください。Viteなら `assetBase={import.meta.env.BASE_URL + 'fields/tsuruse/'}` が使用できます。既存アプリのファイル変更・公開はこの納品に含まれていません。

`paused={true}` で移動を停止できます。アンマウント時にはイベント、描画ループ、区画キャッシュを解放します。プレイヤーは虫取り網を持った簡易描画で、過去に生成した歩行スプライトは未組み込みです。

## 素材・座標の仕様

|項目|仕様|
|---|---|
|元地図座標|2048 × 1885、左上原点、右がX＋、下がY＋|
|通常歩行倍率|8 CSS px / 元地図1単位|
|通常歩行の論理サイズ|16384 × 15080 CSS px|
|区画寸法|元地図64 × 64単位、端は残り寸法|
|詳細素材|557枚の独立SVG、通常1024 × 1024の固有サイズ|
|密度|元地図1単位を16pxで描画。8倍表示×DPR2まで対応|
|表示|6倍以上で詳細区画、低倍率では軽量な全体図|
|読込|画面内を中心から優先＋周辺4区画、同時3件|
|保持|最大24区画。描画済みRGBA換算で通常約96MiB＋全体図等。ブラウザー実装で変動|
|失敗時|全体図を背景に残し、5秒後から再試行。「区画を再読込中」と表示|
|当たり判定|map.jsonのroadRuns。前版の道路候補227599画素を維持|
|歩行方式|足元1点判定、連続移動の細分化、道路タップで経路探索|

`tiles.json` の各項目の `x,y` は区画番号です。配置座標は `x*64,y*64`、`width,height` は元地図座標単位です。SVGはグローバル座標のviewBoxを持ちますが、Canvasに描くときは指定位置・指定寸法で配置してください。標準ビューアーがこの処理を行います。

表示する区画が24枚を超える非常に広い画面では、中心近くを詳細化し、外周は全体図を残します。将来、絵を描き込んだ背景に交換する場合も、区画の範囲・位置を固定して画像を差し替えられます。

## 精度と残る確認事項

- 元地図から抽出した道路を判定基準としています。元画像より細かい現地情報を復元したものではありません。
- 見た目の輪郭は軽く平滑化しています。通行判定は元画素のままです。道端の細かな見た目と足元判定が一致しない場所があります。
- 建物形状は色抽出による推定。隣接する建物が一体に見える箇所があります。屋根色、窓、屋根設備、樹木は装飾です。
- 道路は111個の接続成分に分かれています。文字や地図の継ぎ目による切れ、立体交差などは自動接続していません。`review-points.json`を参照してください。
- この広域版では緑色の場所を一律に歩行可能にはしていません。公園の入口・立ち入り範囲は別途確認が必要です。以前のゆうゆうの丘公園・アンビシャスの独立フィールドとは別データです。
- 元地図のラベルや実際の駅入口、踏切位置の正確性は保証していません。
- Nodeで通行・経路・キャッシュ・読込上限・ファイル配置を検証済み。SVGはPNGに描画して目視確認しています。ブラウザー実行環境の取得に失敗したため、実ブラウザーとスマホ実機での操作・速度・メモリー使用量は未検証です。

## 再生成と検証

`build_tiles.py` は同梱の `terrain.bin` を入力にSVG群を再生成します。Python依存は numpy/scipy/contourpy。`assets/overview.svg` をPNGにレンダリングしてから `build_preview.py` を実行すると確認HTMLも更新されます。

```sh
node tests.mjs
node tile-tests.mjs
```

地図画像や当たり判定を編集した場合は、建物への侵入、横断箇所、公園への出入りを実機で確認してください。
